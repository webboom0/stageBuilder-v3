# StageBuilder 기획 의도 및 v3 현황 분석

**작성일:** 2026-08-26  
**대상:** StageBuilder v4 재구축 기획  
**근거:** v3 코드·문서·운영 피드백·사용자 요구

---

## 1. 기획 의도 (제품이 해결하려는 것)

StageBuilder는 **공연·무대 연출 전문가**가 다음을 **한 화면(3D + 타임라인)**에서 설계·시뮬레이션·재생하는 **전문가용 무대 연출 에디터**입니다.

| 축 | 의도 |
|----|------|
| **공간** | 프로시니엄·아레나 등 **실제 공연장 규모**에 맞춘 무대 위에 캐릭터·소품·조명을 배치 |
| **시간** | 모션·조명·오디오·등장/퇴장을 **타임라인**으로 동기 재생 |
| **연출** | 1막·2막처럼 **씬(막) 단위** 작업 후, 전체 또는 씬별 렌더·리허설 |
| **현장 연동** | Show Control(그룹 GO), HOUSE·Fixture 조명, 무대연출 프리셋으로 **실공연 워크플로**에 가깝게 |
| **협업·보관** | 서버 `files/` 구조와 맞는 **프로젝트 폴더** + 필요 시 **ZIP 내보내기** |

한 줄로: **「무대 위에서 무엇이, 언제, 어떻게 보이고 들리고 밝아지는가」**를 디지털 트윈으로 만드는 도구.

---

## 2. v3에서 드러난 강점 (유지·발전)

- Three.js 기반 3D 뷰 + Premiere 스타일 **멀티 트랙 타임라인** (Motion / Light / Audio)
- FBX 모션, FixtureEngine, HOUSE 채널, Show Control 그룹 GO
- 서버 연동 업로드 (`/api/upload-*`, `/files/...` 정적 서빙)
- ZIP 분할 저장(`DataSplitter`)으로 대형 씬 JSON 관리
- 무대연출 패널(회광반조 등)로 **프리셋 기반 빠른 리허설**

→ v4는 **기능을 빼는 것이 아니라**, 같은 의도를 **통일된 모델과 코드 구조**로 다시 구현합니다.

## 3. v3 구조적 문제 (보완 대상)

### 3.1 기획·아키텍처

| 문제 | 영향 |
|------|------|
| 기능 추가 중심, **공통 타임라인/키프레임 모델 부재** | 모션·조명·오브젝트마다 추가/삭제/이동/편집 UX·코드가 다름 |
| `Editor.js` vs `core/Editor.js` 등 **이중 구조** | 기여자·AI 에이전트 모두 혼란, 죽은 코드 |
| `window.editor`, `window.timeline` 등 **전역 의존** | 탭·테스트·리팩터링 어려움 |
| Motion/Light/Audio 각 **6~8천 줄** 단일 파일 | 회귀·통일 작업 비용 폭증 |

### 3.2 타임라인·키프레임

| 문제 | 영향 |
|------|------|
| 모션 **클립 길이 조절 = 등장/퇴장** | 조명·오디오와 개념 불일치; 클립 줄이면 캐릭터만 사라짐 |
| 조명 **이중 저장** (`TimelineData` + `lightTracks` JSON + 마이그레이션) | 저장/로드 버그, 키 UI 중복 다이아몬드 등 |
| 타임라인 **총 길이 변경** 시 키·클립 **비율/절대시간** 혼재 | 늘리기/줄이기 후 위치 어긋남 |
| 오디오 **잘라내기·붙이기·트림** 미흡 | DAW/기존 에디터 대비 편집성 부족 |

### 3.3 프로젝트·씬

| 문제 | 영향 |
|------|------|
| **단일 씬** 중심 (막/회차 분리 약함) | 1막·2막 연출을 한 타임라인에 억지로 넣음 |
| 저장 = **ZIP 다운로드** 중심 | 서버 `files/`와 동일한 **폴더형 프로젝트**·목록 UI 없음 |
| ZIP에 **FBX·음원 바이너리 미포함** | PC 간 이동 시 깨짐 (설계 한계로 문서화만 됨) |

### 3.4 무대·공간

| 문제 | 영향 |
|------|------|
| 무대 **임의 스케일·오프셋** | 프로시니엄/아레나 **바닥 크기·중심 불일치** |
| 배경 FBX만 바꾸고 **동일 StageProfile 미적용** | 객체·조명·그리드 기준점이 공연장마다 달라짐 |
| 모션 캐릭터 **실제 키(170cm) 기준 스케일** 미정의 | 연출자가 크기 감각 잡기 어려움 |

### 3.5 서버·환경

| 문제 | 영향 |
|------|------|
| 로컬 API 포트·origin **설정 분산** (audio 3001, pivot 3000 등) | 배포·로컬 전환 시 수동 수정 |
| pivot `server.js`와 **로컬 dev 서버 불일치** | 업로드 경로·인증 동작 차이 |

### 3.6 문서·품질

| 문제 | 영향 |
|------|------|
| 기능 추가 후 **튜토리얼·R&D 정리 지연** | 제출·온보딩 부담 |
| 인앱 가이드 없음 (별도 과제) | MD/PDF 튜토리얼 의존 |

## 4. v4에서의 핵심 설계 방향 (요약)

### 4.1 통일 키프레임 모델

모든 트랙(모션 transform, `visible`/`opacity`, 조명 dim/pan/…, 오브젝트 속성)은 공통:

- **추가 · 삭제 · 선택 · 드래그 이동 · 값 편집 · 보간(easing)**
- UI: 다이아몬드 1개/시각(가상 트랙), 동일 단축키·컨텍스트 메뉴

### 4.2 등장/퇴장 = 클립 리사이즈 ❌ → Exit/Opacity ✅

- **클립**: 해당 객체/그룹의 **타임라인 상 존재 구간** (고정 또는 이동만)
- **보였다/안 보였다**: `visible` 또는 `opacity` **키프레임** (+ Show Control `endsWithExit`는 키로 표현)
- 조명·오디오·무대 오브젝트와 **동일 개념**

### 4.3 멀티 씬(막)

```
Project
├── scenes[]          // 1막, 2막, …
│   ├── duration
│   ├── stageProfile
│   ├── timelines     // motion / light / audio refs
│   └── showControl
├── projectList UI
└── render: all | single scene
```

### 4.4 저장 전략 (하이브리드)

| 계층 | 방식 |
|------|------|
| **일상 작업** | 서버 `files/projects/{projectId}/` — JSON + 상대 경로로 music/fbx 참조 (무대연출 패널처럼 목록·즉시 열기) |
| **배포·백업** | **내보내기 → ZIP** (선택: 에셋 포함 / 링크만) |
| **용량** | 기본은 **링크형**; “완전 패키지”는 옵션 + 진행률·용량 경고 |

### 4.5 무대 표준 (예술의전당 오페라극장 기준)

- 국내 **대공연장** 일반 규격(가로 15~20m, 깊이 10~14.5m) → v4 **StageProfile** 기본값 **16×13.5m**
- 예술의전당 오페라 **450㎡** (20×22.5m) 등은 **프리셋**으로 선택 가능
- 프로시니엄·아레나: **동일 StageProfile 바닥** + 배경/프로시니엄 아치만 교체
- 원점: **무대 바닥 중앙**; 170cm 휴머노이드 = 1.7 unit (meter 스케일)

### 4.6 로컬 = pivot 서버 호환

- v4 `server/`는 pivot `server.js`의 StageBuilder 관련 라우트·`files` 루트·multer 규칙 **동일**
- 클라이언트: **`API_BASE_URL` 단일 변수** (로컬 `http://localhost:3000`, 운영 `origin`)

## 5. v3 → v4 이식 vs 재작성 기준

| 영역 | 전략 |
|------|------|
| TimelineCore, TrackData, INTERPOLATION | **이식 + 정리** |
| FixtureEngine, HOUSE, Show Control 도메인 | **이식 + 인터페이스 분리** |
| MotionTimeline/LightTimeline/AudioTimeline UI | **재작성** (공통 TimelineShell + 플러그인 트랙) |
| DataSplitter | **프로젝트 폴더 스키마**로 대체; ZIP은 export 레이어 |
| Sidebar.Nanseol 등 공연 하드코딩 | **프리셋 JSON**으로 외부화 (점진) |

## 6. 성공 기준 (v4 1.0)

1. 모션·조명·오브젝트 **키 조작 UX 동일**
2. 클립 리사이즈로 visibility 제어 **제거**, opacity/exit 키로 통일
3. 씬(막) 추가·목록·씬별/전체 재생·렌더 경로 존재
4. 프로젝트 폴더 저장 + 무대연출식 목록 + ZIP 내보내기
5. 예술의전당 기준 StageProfile, 중앙 정렬, 170cm 기준 배치
6. 로컬 서버 = pivot 호환, `API_BASE_URL`만 바꿔 연결
7. 타임라인 길이 변경 시 키·클립 **일관 규칙** (절대 초 기준)
8. 기능 단위 **튜토리얼 + R&D 작업정리** 동행
