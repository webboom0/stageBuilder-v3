| API config 분산 | API_BASE_URL |
| 6000+ line timeline files | domain modules |

### 6.4 Phase 3 — 모션 (진행)

#### 문제점
- v3: 클립 width = visibility, endsWithExit 이중 규칙
- 초안: 속성마다 6트랙 + 스케일 1.7 world unit → 무대에서 안 보임
- 단일 vs 그룹 UX 불일치 · Properties에 객체/스크립트 탭 혼선
- 구간 From/끝 X 입력에 무대 픽 소수 자릿수가 넘쳐 패널 밖으로 깨짐
- Assets 업로드 시 IDE 파일 감시로 에디터 전체 리로드 위험

#### 수정 내용 (v3 정렬 · 안정화)
- **1 객체 = 1 트랙** + 트랙 색 · compound 키 (pos/rot/scale/opacity/visible)
- 스폰: 건물 FBX Y 유지 · W×D · **HUMAN_STAGE_SCALE≈0.24** · 간격 ~0.7m · 카메라=덱 중심
- Properties 탭 **속성 / 구간** (스크립트 제거)
  - **속성**: 위치·Y회전 칩·틴트·Opacity·무대 픽·선택 키
  - **구간**: 이동/대기/퇴장 (포메이션 없음) · **구간 적용** → 그룹 GO와 동일 키 파이프라인 (퇴장은 구간만)
- 그룹 Ensemble: 색상 픽커 · Opacity · 이동/대기/퇴장 · 포메이션 · GO
- 그룹·단일 구간 폼: **좌표 소수점 2자리** + CSS `minmax(0,1fr)`로 입력칸 오버플로 방지
- Assets 업로드/삭제: **목록만 갱신** · `server/files/**` `.cursorignore`
- 키 동일 시각 중복 금지 · 드래그 겹침 방지 · 보임/안보임 UI 제거(퇴장·opacity)
- 트랙 삭제 → 스테이지 메시 제거 · Skinned FBX frustum cull 비활성
- 타임라인: 키 클릭→무대 선택·스크럽 · M / Shift+M · 스크롤바 슬림
- **Smooth 보간 복구**: v3처럼 `smoothstep` ease-in/out, `Linear`와 실제 차이 적용
- **퇴장**: 속성 탭 제거 · **구간** 탭(+퇴장)만 사용
- **v3 motion JSON import**: 어댑터 코드만 보유 · **메뉴/UI 미노출(보류)**
- **사용 안내 진본**: `editor/tutorial/` · `/stageBuilder/tutorial/` · MD 동기화
- Characters / **Stage** 분리 · Stage 기본 메시(직육면체·원통) · 속성 XYZ
- **Video 배경**: Assets **+** 재생 · 재생 중 **−** 제거 · 프로시니엄 스크린 패널·램프 자동 숨김 (뒤 벽 유지)

### 6.21 조명 트랙 연결 — 전용 트랙 + 연결 끊기 (2026-09-03)

#### 문제점
- bake와 수동 키 편집이 동일 트랙을 공유 → 수동 수정 후 re-bake 시 수동 작업 소실
- 저장된 문장과 실제 키프레임이 불일치

#### 설계 — fixture당 트랙 1개 · 명시적 전환
조명기 1대는 한 순간에 한 방향·한 밝기만 출력하므로 두 레이어를 동시에 렌더할 수 없다. 따라서 **레이어 합성이 아니라 소유권 전환** 모델을 채택.

- bake는 **연결 전용 트랙**(`light:fx:{fid}:link`, `source: 'linked'`, `locked: true`)에 기록
- 연결 트랙은 **자물쇠 해제 불가** (버튼 비활성 · 그룹 일괄 잠금 제외) — bake·전 키 패치 중에만 내부적으로 임시 해제
- 손으로 고치려면 **「연결 끊기」** — `unlinkTrack()`이 그 트랙을 제자리에서 수동 트랙으로 전환:
  `group` → `light:fx:{fid}` · `source` → `null` · `locked` → `false` · `fixtureFollowPrompt`·`linkMotionTrackId`·`linkSourceHash` → `null` · 이름 → `FX {id} · {행}`
  **키는 그대로 유지**되고, 캐릭터와의 연결만 끊어짐 (확인 다이얼로그로 경고)
- 진입점은 **연결 박스의 「연결 끊기」 버튼 하나로 통일** (선택 fixture 일괄). 타임라인 트랙 헤드에는 전환 메뉴를 두지 않음 — 트랙 선택/우클릭 흐름을 방해하지 않도록
- 같은 fixture에 이미 수동 트랙이 있으면 전환 거부 (group 충돌 방지)
- `Track.source` 필드 추가 (`'linked' | null`), snapshot/restore 지원
- 트랙 헤드에 **링크 아이콘 뱃지** (이름은 수동 트랙과 동일한 `FX {id} · {행}`)
- `apply()`는 구버전 저장본 호환용으로 연결·수동 동시 존재 시 **수동 우선** 처리 유지
- 「선택 속성 → 전 키」(§6.20)는 연결·수동 양쪽 모두에 반영

#### 「AI」 → 「트랙 연결」 재정의 · 자연어 입력 제거
기능이 **항상 캐릭터 트랙을 필요로 하고**(대상 없이는 초안 자체가 생성 불가), 내부도 ML이 아니라 한국어 정규식 파서였다. 「AI」는 실제 동작을 설명하지 못하고 좌표 직접 지정 같은 과잉 기대를 유발했다. **연결**로 재정의하면:

- 잠금이 자명해짐 — 캐릭터에서 계산된 파생 값이라 직접 편집 불가
- 이미 있는 **위치 프리셋 링크**(`positionPresetLinks.js`의 `propagatePositionPresetUpdate`·`unlinkPositionPreset`)와 용어·조작이 일치
- 「연결 끊기」가 「수동으로 변경」보다 결과를 그대로 설명

나아가 **자연어 입력 자체를 걷어냈다**. 문장으로 받던 정보는 사실상 「어느 캐릭터냐」 하나였고(구간·머물기는 대부분 캐릭터 타이밍과 중복), 파서가 문장을 못 알아듣는 실패 경로가 UX의 대부분을 차지했다. **검색 팝업으로 캐릭터만 고르면** 나머지 타이밍은 캐릭터 트랙에서 그대로 유도한다.

| 이전 | 변경 |
|------|------|
| AI 조명 시퀀스 | 트랙 연결 |
| `@캐릭터 …따라가다가 40초까지…` 문장 입력 | **캐릭터 검색 팝업** (입력할 때마다 목록 필터) |
| 초안 보기 / 키프레임 적용 | 연결하고 키 만들기 |
| `AI` 뱃지 | 링크 아이콘 뱃지 |
| 수동으로 변경 | 연결 끊기 |
| 수정 후 다시 적용 | 연결 갱신 |
| `source: 'ai-follow'` · group `:ai` | `source: 'linked'` · group `:link` |
| `fixtureFollowDraft.js` · `fixtureFollowUi.js` | `fixtureLinkDraft.js` · `fixtureLinkUi.js` |

- 삭제된 코드: `parseFollowPhases`·`parseKoreanTimeSpan`·`resolveMotionMention`·`TIME_TOK` 정규식, `@` 멘션 자동완성 메뉴·구문 하이라이트 오버레이(`wireTrackMentions`·`collectTrackMentionRanges`·`colorFollowKeywords`) — 캐릭터 AI 패턴(`segmentStepUi.js`)은 계속 자연어를 쓰므로 공용 CSS는 유지
- 구버전 저장본 호환: `normalizeTrackSource()`가 `'ai-follow'` → `'linked'`로 정규화, `parseFixtureFidFromGroup`·`isLinkedFixtureGroup`이 `:ai`·`:link` 양쪽 인식, `ensureLinkTrackForFid()`도 접미사 무관하게 기존 트랙을 찾아 제자리 re-bake
- 옛 저장본의 `fixtureFollowPrompt`(`@이름` 문장)는 `legacyMotionTrackId()`가 이름으로 트랙을 되찾아 검색 트리거에 표시 — 연결 대상이 유실되지 않음

문장이 없어진 만큼 phase는 캐릭터 트랙에서 계산한다 (`motionTimeRange()`).

- **follow**: `presenceClip.startSec`(등장 리드 포함) → `bodyOut`. body만 쓰면 초반에 키가 없어 조명이 늦게 켜짐
- **exit**: 캐릭터가 퇴장으로 끝나면 그 구간 동안 **계속 따라가면서 dim을 0까지 선형 감쇠**. 단순 소등이 아니라 퇴장 동선을 비추며 사라지므로 실제 팔로우스팟 운용과 같다
- 퇴장 판정 — presence 트랙은 `presenceEndSec > presenceOutSec`(lead-out 존재), 일반 키 트랙은 **마지막 키의 `visible === false` 또는 `opacity ≤ 0.05`**
- 퇴장이 없으면 exit phase 없이 마지막 조준을 유지
- phase 종류가 `follow`/`exit` 둘로 줄면서 bake 루프도 통합 — 조준 계산을 `aimAt(t)` 하나로 뽑고 phase는 dim 곡선만 다르게 지정

#### 「갱신 필요」 감지 — 연결을 살아있게
「연결」이라고 부르는 이상 캐릭터 동선을 고치면 조명도 반응해야 한다. 다만 **자동 재계산은 채택하지 않았다** — 드래그 중 매 프레임 re-bake는 undo 히스토리를 수천 개로 오염시키고 선택을 계속 빼앗는다. 대신 **변경을 감지해 표시하고, 갱신은 사용자가 누른다**.

- `fixtureLinkState.js` — bake가 읽는 모든 입력의 지문(FNV-1a): presence clip 봉투(`startSec`/`leadIn`/`leadOut`/`bodyIn`/`bodyOut`·enter/exit pose) + 각 모션 키의 `timeSec`·`position`·`visible`·`opacity` + **fixture 자신의 위치**(조준 원점이므로 동일하게 영향)
- 부동소수 노이즈로 오탐하지 않도록 위치 `1e-3`·시간 `1e-4` 단위로 양자화
- bake 종료 시 `stampLinkSource()`가 `linkMotionTrackId`·`linkSourceHash`를 트랙에 기록 (저장본에 포함)
- `keys`·`tracks` 이벤트를 **200ms 디바운스**로 받아 `refreshLinkStaleFlags()` 실행 — 실제로 플래그가 바뀔 때만 `tracks` emit
- 표시: 트랙 헤드 링크 뱃지 **주황색 + 회전 아이콘**, 연결 박스 상태줄 경고, 적용 버튼이 **「연결 갱신」**으로 전환

#### 함께 고친 성능 버그 — bake의 과잉 리렌더
- **증상**: 「적용」 한 번에 타임라인이 fixture당 약 88회(삭제 44 + 추가 44) 다시 그려짐. 3대 선택 시 264회
- **원인**: `TimelineEngine.addKeyframe`·`removeKeyframe`이 **호출마다** `emit('keys')`. `beginKeyframeBake()`/`endKeyframeBake()` 억제 장치가 이미 있었지만 조명 bake만 사용하지 않고 있었음
- **수정**: bake 루프 전체를 `beginKeyframeBake()`/`endKeyframeBake()`로 감싸 **emit 264회 → 2회**. 내부 루프는 `bakeIntoLinkTracks()`로 분리하고 `try/finally`로 짝 보장

#### 함께 고친 버그 — `K` 단축키 오작동
- **증상**: 잠긴 조명 트랙을 선택하고 `K`를 누르면 **캐릭터 모션 트랙에 키가 추가**됨
- **원인**: `resolveTrackId()`가 잠긴 트랙을 `isKeyableTrack === false`로 걸러낸 뒤 폴백 체인 끝의 「첫 모션 트랙」까지 흘러감 (연결 트랙 도입 이전에도 잠긴 트랙 선택 시 동일한 오동작)
- **수정**: 사용자가 지목한 트랙이 잠겨 있으면 **폴백 금지** — `null` 반환(무동작). 잠긴 연결 트랙에서 `K`를 눌러도 다른 트랙이 오염되지 않음
